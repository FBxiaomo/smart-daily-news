# 本地历史、收藏与七日回顾

日报预览与已生成的投递快照保存在本地 SQLite，默认长期保留；没有自动删除。
历史可按标题、正文、来源等文本搜索；可手动删除预览和已全部发送成功的期次。
待发送、失败、正在发送及结果不确定的期次不能删除，以免破坏原有恢复流程。

收藏保存一份独立的文章来源和链接快照。按规范化链接去重，同一篇文章多次收藏只保留一份；
删除原日报不会删除收藏。可单独搜索或移除收藏。备份整个数据库才能一起备份这些数据。

`archive_previews`、`archive_favorites` 由模块按需创建，已有数据库的 `user_version` 不变。
已完成的期次清理内容后，只保留一个完成标记防止同一期自动重复生成或发送；
不保留已删除日报的正文。收藏、来源缓存与用户额外导出的文件需另行清理。
周报预览删除后保留不包含正文的期号标记，用来防止已发周报被再次纳入未来周报。

## 七日回顾

回顾统计过去 **168 小时**生成的本地普通日报快照，包括未发送的手动预览和已生成的投递快照。
同一个原文链接先做去重，保留该链接最近出现的文章信息；然后按保守标题相似度合并可能相同的事件。
对入选事件优先排序不同 RSS 来源数，其次为独立文章数，保留原文链接与来源。

- 相同链接只计一次，不因同一篇新闻出现在多期日报而增加热度。
- 七日回顾预览和本模块生成的已发回顾不会参与后续回顾；删除预览也不影响这一排除规则。
- 输出标题、原文摘要及来源链接，不自动使用 AI 编造回顾结论。
- 每个事件最多展示 12 篇文章；指标中记录实际独立文章数和来源数，超过上限会显示提示。
- 本地数据可能只有少数用户自选来源，因此它表示 **本地订阅覆盖的相对热度**，不代表全网热度或可信度。
- 语义不同但标题相似的新闻可能被误合并；跨语言或标题差异较大的同一事件可能无法合并。
- 若没有可用文章，会明确报告先保存日报；最多处理 1000 期和 2000 篇独立文章，超限时要求清理历史。

接口示例：

```python
from daily_news.archive import save_preview, list_history, favorite, weekly_digest

id = save_preview(state, digest)
records = list_history(state, query="汽车")
favorite_id = favorite(state, id, digest.stories[0].articles[0].id, now)
weekly, metrics = weekly_digest(state, cfg, now, "weekly-2026-10-27")
weekly_id = save_preview(state, weekly, kind="weekly")
```

`list_history` 的 ID 使用 `preview:<uuid>` 或 `edition:<期号>`；`kind` 分别为
`preview`、`weekly`、`edition`。`status` 呈现预览或投递状态，`can_delete` 标识是否可清理。
`weekly_digest` 返回的 `metrics` 包括时间窗口、参与快照、独立文章数、事件数、订阅源数、
多来源事件数及各展示事件的来源/文章数；所有结果均基于现有数据而非外部排名。

清理完成期次会保留 `jobs.status=complete` 标记。调度器必须把“完成标记存在但快照已清理”
视为已完成，不能重新生成或重发。任何恢复或手动重试流程都需遵守这一约束。

## 维护

历史与收藏不包含原始模型密钥或邮箱授权码，但可能包含私人 RSS 标题、摘要及 URL；
请按已有数据目录权限保护，并使用程序的 SQLite 备份方式。历史和收藏均没有自动过期策略。
